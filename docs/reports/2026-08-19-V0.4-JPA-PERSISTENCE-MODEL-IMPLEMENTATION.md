## Mapping strategy

Entities are package-by-feature directly under the owning `vn.pes.<module>` package, matching the repository’s existing module package convention. Every FK is a scalar `Long ...Id`; there are no entity associations, collections, EAGER fetches, or cross-module entity imports. All IDs are `Long` with IDENTITY generation.

`DATETIME(3)` uses `LocalDateTime`; `DATE` uses `LocalDate`; decimal columns use `BigDecimal` with accepted precision/scale; text types use explicit `TEXT`/`LONGTEXT` column definitions. `invitations.code_hash` is `byte[]` with `BINARY(32)` and no raw invitation-code field.

`quiz_attempts.active_guard` is mapped read-only (`insertable=false`, `updatable=false`) as a generated `TINYINT` value. `quiz_configs.version` is mapped with `@Version`.
