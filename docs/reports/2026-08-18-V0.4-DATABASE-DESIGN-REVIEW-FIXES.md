## 4. Owner Clarification 1A — Competition Unit Attribution

**Approved 2026-08-18.**

Semantics:
- For each competition period, one user is attributed to exactly ONE Tiểu đội.
- The Tiểu đội is determined by the organization assignment effective at `competition_period.ends_at`.
- No point-sharing across multiple Tiểu đội within the same period.
- Tiểu đội drives derivation of Trung đội and Đại đội.
- When period CLOSED: attribution must be snapshot/stabilized.
- Reassignment after period closes does NOT change historical attribution.
- The overlap condition `effective_from <= period_end AND effective_to >= period_start` is FORBIDDEN for this purpose.

**Schema response:** Introduced `comp_member_attributions` table with UNIQUE(period_id, account_id). Attribution at `period.ends_at`. Closed-period rows immutable. Unit aggregation derives from unique attributed member population.

**Recorded in:** `docs/v0.1/BUSINESS-REQUIREMENTS.md` §19.12.

## 5. Owner Clarification 2A — Quiz/Weekly Source Semantics

**Approved 2026-08-18.**

Semantics:

**QUIZ:**
- Quiz owns grading/result/ranking semantics.
- Highest eligible FINAL graded attempt is used for source selection.
- Only PASS result may produce a competition contribution.
- FAIL result produces no contribution.
- Timeout-finalized graded result remains valid.
- Competition owns whether/how the valid source contributes points.
- Competition policy supplies Admin-configured value/weight.

**WEEKLY:**
- Correct final Weekly submission may produce a competition contribution.
- Incorrect result produces no contribution.
- Point value/weight is Admin-configured in Competition policy.

**MANUAL ADJUSTMENT:** Preserve existing bonus/penalty semantics. No new numeric formula invented.

**Schema response:**
- Removed `is_competition_eligible` from `quiz_results` and `weekly_submissions`.
- Quiz ranking is now based on `is_passed=1` and highest `raw_score` — independent of Competition module.
- Added UNIQUE(period_id, quiz_result_id) and UNIQUE(period_id, weekly_submission_id) to `comp_contributions`.
- Competition module derives eligibility from `quiz_results.is_passed=1` and `weekly_submissions.is_correct=1`.

**Recorded in:** `docs/v0.1/BUSINESS-REQUIREMENTS.md` §19.13.

## 9. Quiz Snapshot Correction

**Before:** `quiz_attempt_questions` snapshots question text. `quiz_attempt_answers` references mutable `quiz_question_options.id`. Historical grading requires current live bank.

**After:** New `quiz_attempt_question_options` table is created when the attempt question set is created. It contains `option_text_snapshot`, `is_correct_snapshot`, `position`, and a trace `source_option_id` (SET NULL on delete — does not affect snapshot). `quiz_attempt_answers.selected_attempt_option_id` → FK to `quiz_attempt_question_options.id`. Admin can edit question/options freely; existing attempts are completely unaffected.

**DB enforcement:** UNIQUE(attempt_question_id, position) on `quiz_attempt_question_options`. `selected_attempt_option_id` FK RESTRICT.

---

## 10. Quiz Lifecycle/Concurrency Correction

**ABANDONED removed:** BD-V04-007/008 do not approve abandonment. V1 terminal states: ACTIVE → SUBMITTED or TIMEOUT_FINALIZED only.

**Mutability:** Answers are mutable during ACTIVE (resume semantics); immutable after SUBMITTED or TIMEOUT_FINALIZED. Common Column Policy updated.

**DB guard:** Generated column `active_guard` = CASE WHEN status='ACTIVE' THEN 1 ELSE NULL END. UNIQUE(account_id, quiz_config_id, active_guard). MySQL NULL distinctness allows multiple terminal rows. First concurrent INSERT of ACTIVE is handled by DB UNIQUE violation without requiring SELECT FOR UPDATE on non-existing rows.

**Attempt number:** UNIQUE(account_id, quiz_config_id, attempt_number).

## 11. Quiz/Competition Ownership Correction

**Before:** `quiz_results.is_competition_eligible` flag used for both ranking and competition source selection.

**After:**
- Quiz ranking: `WHERE is_passed=1 ORDER BY raw_score DESC`. No dependency on Competition.
- Competition: derives eligible source from `is_passed=1` (quiz) or `is_correct=1` (weekly) + competition period membership.
- `is_competition_eligible` removed from both Quiz and Weekly modules.
- `comp_contributions` source uniqueness enforced by UNIQUE(period_id, quiz_result_id) and UNIQUE(period_id, weekly_submission_id).

---

## 12. Unit Attribution Correction

**Before:** Attribution query `effective_from <= period_end AND effective_to >= period_start` can select two Tiểu đội for mid-period transfer.

**After:** New `comp_member_attributions` table. UNIQUE(period_id, account_id). Attribution determined from assignment effective at `comp_periods.ends_at` via `user_assignment_history`. Derives tieu_doi_id → trung_doi_id → dai_doi_id. Source trace: `source_assignment_history_id` (FK SET NULL — does not invalidate attribution).

**Aggregation:** Each user counted once. Trung đội/Đại đội normalized average computed from distinct leaf member population — not from summing unit subtotals.

**Closed-period stability:** CLOSED period rows immutable. Open period rows may be deleted and reinserted on recalculation.

**Edge case:** If no valid Tiểu đội exists at `period.ends_at` — user is NOT attributed. No business eligibility invented.

## 13. Competition Source/Uniqueness Correction

- UNIQUE(period_id, quiz_result_id) — MySQL nullable UNIQUE; NULLs distinct; prevents duplicate canonical Quiz contribution.
- UNIQUE(period_id, weekly_submission_id) — same semantics for Weekly.
- Source type single-FK rule: exactly one of (quiz_result_id, weekly_submission_id, manual_adjustment_id) is non-NULL per row.
- Application enforces source_type consistency with populated FK.
- Design prevents "attempt farming": highest PASS result per quiz_config_id per period is the canonical source; UNIQUE constraint prevents duplicate row for the same quiz_result.

## 14. Competition Policy-Version Correction

`comp_policies` is versioned:
- Changes to scoring semantics for future use create a new policy row.
- Closed periods keep their original policy FK.
- Old policy's `effective_to` is set when superseded.
- No in-place mutation of scoring semantics once a period references the policy.

## 15. Weekly Lifecycle Correction

- Removed ISO-8601 week assumption from `period_week`.
- `period_opens_at`/`period_closes_at` are authoritative DATETIME(3) fields (NOT NULL).
- `period_year` and `period_week_label` are now optional display-only labels (nullable); they do NOT define ISO semantics.
- `period_status` is a derived lifecycle state — NOT an independent timing authority.
- Removed `reveal_after_close` — it made a mandatory business rule configurable; rule is hardcoded: correct explanation revealed after `period_closes_at`.
- UNIQUE constraint changed from `(period_year, period_week)` to `(period_opens_at)`.
- BD-V04-010 is RESOLVED. Exact timezone/boundary configuration deferred to implementation.

## 21. Query-Scenario Revalidation

| Scenario | Resolution |
|---|---|
| First concurrent Quiz attempt | DB UNIQUE on generated `active_guard` — INSERT of second ACTIVE violates constraint |
| Concurrent second start request | Same guard — DB rejects second ACTIVE INSERT |

| Admin edits question/options during ACTIVE attempt | Snapshot unaffected; live bank edit transparent to existing attempts |
| Timeout grading after live bank edit | Grading uses `is_correct_snapshot` — independent of live bank |

| Quiz ranking without Competition rows | Ranking uses quiz_results only; no Competition dependency |
| Quiz competition contribution creation | UNIQUE(period_id, quiz_result_id) enforces single canonical contribution |
| Duplicate contribution retry | UNIQUE violation; idempotent upsert pattern |
| Weekly correct contribution | `is_correct=1` → Competition creates contribution; UNIQUE(period_id, weekly_submission_id) |
| Weekly incorrect — no contribution | `is_correct=0` → Competition does not create contribution row |
| User transfers Tiểu đội mid-period | `comp_member_attributions` uses assignment at `period.ends_at`; UNIQUE(period, account) |
| Unit ranking at period close | Aggregate from `comp_member_attributions`; no double-counting |
| Closed-period reassignment after close | `comp_member_attributions` CLOSED rows stable; no recalculation |
| Policy replacement | New `comp_policies` row; old FK on closed periods stable |
| Authorized closed-period correction | `comp_corrections` INSERT; original contribution immutable |
| Invitation concurrent consume | SELECT FOR UPDATE row lock; single transaction |
| External Resolution video/link | document_type='LINK' → external_url NOT NULL; file_metadata_id NULL; no dummy file |
