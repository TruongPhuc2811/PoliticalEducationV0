## 1. Task understanding

Understanding: **100%**. The task corrects the Weekly current-window repository contract to bind both half-open interval predicates to one authoritative application-supplied business instant. It does not introduce lifecycle status, scheduling, service/API behavior, database-time functions, schema changes, or corrupt-data resolution.

## 2. Finding and root cause

The previous derived method accepted two independent values:

```java
Optional<WeeklyQuestion> findByPeriodOpensAtLessThanEqualAndPeriodClosesAtGreaterThan(
        LocalDateTime now, LocalDateTime sameNow);
```

Its predicates were `periodOpensAt <= :now` and `periodClosesAt > :sameNow`. They represented the accepted Weekly lifecycle only when the caller happened to provide equal instants. The repository signature did not enforce that precondition, weakening the contract.

`docs/v0.4/DATABASE-DESIGN.md` defines the Weekly period overlap invariant as application-enforced and the runtime lifecycle as derived only from its opening and closing boundaries. The repository therefore accepts one supplied business instant and remains a minimal lookup.

## 3. Corrected contract

```java
Optional<WeeklyQuestion> findCurrentAt(@Param("now") LocalDateTime now);
```

The module-local JPQL is exactly:

```jpql
q.periodOpensAt <= :now
AND q.periodClosesAt > :now
```

The inclusive opening boundary and strict closing boundary preserve the accepted half-open interval `[periodOpensAt, periodClosesAt)`. `:now` is supplied later by the application as the authoritative business instant. No native SQL or database clock function (`CURRENT_DATE`, `CURRENT_TIMESTAMP`, `NOW()`, or `CURDATE()`) is used.

The accepted no-overlap application invariant remains the authority for cardinality. This repository does not add a scheduler, stored status, ordering, limit, lock, or speculative tie-breaker for corrupt overlapping rows.

## 7. Runtime, data, and performance review

The corrected JPQL remains a single bounded entity lookup; it adds no loop, allocation pattern, lock, write, transaction boundary, background behavior, or database clock dependency. It changes only the query contract: callers cannot accidentally supply different opening and closing comparison instants.

The query returns `Optional<WeeklyQuestion>` under the accepted no-overlap application invariant. Corrupt overlapping data could theoretically yield multiple rows; resolving that is intentionally outside this minimal repository contract and requires no data migration or schema change here. MySQL repository integration was not run because a safe dedicated MySQL test database is unavailable.
