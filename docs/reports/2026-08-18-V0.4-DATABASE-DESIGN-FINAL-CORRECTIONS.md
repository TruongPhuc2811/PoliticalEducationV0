## Canonical Competition Quiz Source Model

`comp_quiz_source_selections` is Competition-owned and contains:

- `period_id`, `account_id`, `quiz_config_id`, `selected_quiz_result_id`;
- `selected_at`, `updated_at`, `created_at`;
- UNIQUE `(period_id, account_id, quiz_config_id)`;
- UNIQUE `(period_id, selected_quiz_result_id)`.

Application validation ensures the selected result belongs to the same account/test, is final graded, and is PASS. During an OPEN period, a higher PASS result updates the same selection and associated contribution. CLOSED selections are immutable except through authorized correction. `comp_contributions.quiz_source_selection_id` is nullable-UNIQUE, so a canonical selection produces exactly one canonical contribution.

## Assignment and Snapshot Corrections

- Assignment intervals are `[effective_from, effective_to)` using UTC-compatible `DATETIME(3)`.
- Period-end attribution lookup: `effective_from <= :periodEndsAt AND (effective_to IS NULL OR :periodEndsAt < effective_to)`.
- Transfer writes close the prior interval and open the next at the same instant in one transaction.
- `comp_member_attributions` remains the closed-period population source; it is resolved from assignment history at `comp_periods.ends_at`.
- Quiz attempt snapshots now include question type, text, option order, option text, and correctness. Live source-option deletion only nulls a trace FK.

## Weekly, Constraint, and Integrity Corrections

- Weekly lifecycle derives only from `:nowUtc` and the two DATETIME boundaries: UPCOMING / OPEN / CLOSED. No scheduler or stored status is required.
- Weekly periods cannot overlap: reject `existing.opens < new.closes AND new.opens < existing.closes`.
- `comp_contributions` has DB CHECKs for exactly one source FK and source-type/FK agreement using MySQL-compatible syntax.
- `resolution_documents` has exact-one parent CHECK: `(resolution_id IS NOT NULL) + (topic_id IS NOT NULL) = 1`.
- Manual adjustments preserve amount, type, reason, actor, period, and final contribution-value snapshot. No unapproved numeric multiplier/default has been invented.
