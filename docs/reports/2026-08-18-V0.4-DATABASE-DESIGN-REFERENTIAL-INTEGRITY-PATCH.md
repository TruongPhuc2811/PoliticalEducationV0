## Quiz Option-Parent Integrity

- Added `uq_quiz_aqo_question_id` UNIQUE `(attempt_question_id, id)` on immutable attempt-option snapshots.
- Replaced the independent selected-option FK with composite FK `(attempt_question_id, selected_attempt_option_id) → quiz_attempt_question_options(attempt_question_id, id) ON DELETE RESTRICT`.
- `selected_attempt_option_id` remains nullable: NULL is unanswered; a non-NULL selection must belong to the same attempt-question slot and cannot be deleted.
- `source_option_id` remains nullable `ON DELETE SET NULL` because it is only a live-bank trace reference.

## Weekly Option-Parent Integrity

- Added `uq_weekly_question_options_question_id` UNIQUE `(weekly_question_id, id)`.
- Replaced the independent selected-option FK with composite FK `(weekly_question_id, selected_option_id) → weekly_question_options(weekly_question_id, id) ON DELETE RESTRICT`.
- `selected_option_id` remains NOT NULL, and `uq_weekly_submissions_account_question` still enforces one submission per user/question.
- The existing Weekly freeze and no-Weekly-snapshot design are preserved.

## Quiz Result Denormalized Ownership

Documented the application-enforced transactional invariant for each result and its attempt:

- result account, Quiz config, and finalization source equal the attempt values;
- result creation occurs only within the same grading/finalization transaction as the terminal attempt transition;
- the denormalized values remain for ranking efficiency, while `quiz_attempts` remains source of truth.

## Invitation Initial Assignment History

The single invitation-consumption transaction now explicitly:

1. locks and validates the invitation;
2. creates the account;
3. creates the current Tiểu đội assignment;
4. creates the initial assignment-history row using the same effective instant and `effective_to = NULL`;
5. marks the invitation consumed; and
6. commits, or rolls back all writes on any failure.

## Constraints and Indexes

- Added corresponding composite RESTRICT FKs in the FK Catalog.
- Added Business Constraint, query scenario, delete/update, concurrency, and normalization documentation for the new integrity rules.
- No physical table was added or removed.
