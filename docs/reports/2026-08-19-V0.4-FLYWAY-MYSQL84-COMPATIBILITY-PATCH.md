## 1. Finding

MySQL 8.4 does not permit a column referenced by a CHECK constraint to also use explicit FK `ON DELETE` or `ON UPDATE` clauses. V001 had this incompatibility in `resolution_documents` and `comp_contributions`.

## 2. Why the original static audit missed it

The prior audit counted tables, FKs, CHECKs, and named invariants, but did not correlate each CHECK-referenced column with the referential-action clause on its FK.

## 3. MySQL 8.4 compatibility rule

For CHECK-participating FK columns, explicit referential actions are omitted. InnoDB default `NO ACTION` retains RESTRICT-style delete safety; surrogate `BIGINT AUTO_INCREMENT` parent IDs are immutable, so update cascading is not a V1 operation.

## 4. Affected CHECKs

- `ck_resolution_documents_exactly_one_parent`
- `ck_comp_contributions_exactly_one_source`
- `ck_comp_contributions_source_type`

## 5. Affected FKs and 6. exact changes

4. `fk_comp_contributions_weekly_submissions`

All five FKs remain present with no explicit referential-action clause.
